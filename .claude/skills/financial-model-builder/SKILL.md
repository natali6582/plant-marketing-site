# Financial Model Builder — מודל פיננסי אמין ב-Excel

Skill זה מגדיר **מה הופך מודל לאמין ובטוח**. את מכניקת ה‑Excel (openpyxl, recalc.py, פונקציות נתמכות) קרא מ‑`/mnt/skills/public/xlsx/SKILL.md`. את סדר העבודה (תכנון → אישור → שלב אחד → ראיות) קרא מ‑`disciplined-coding-workflow`.

## 1. חמישה עקרונות שאין לעבור עליהם

1. **הפרדה מלאה: הנחות → חישובים → פלט.** שלושה גיליונות לפחות: `Assumptions`, `Calc`, `Output`. אף נוסחה בגיליון החישוב לא מכילה מספר קשיח — כל קבוע יושב בתא מתויג ב‑Assumptions ומוזכר ב‑`$` מוחלט.
2. **כל מספר ניתן למעקב.** ליד כל הנחה: מקור (מסמך/חוק/המשתמש/ברירת מחדל) ותאריך. הנחה בלי מקור מסומנת `[הנחה — לאישור]` בצהוב.
3. **נוסחה אחת לכל שורה, זהה בכל התקופות.** אין תא ערוך ידנית באמצע שורת תחזית. הסקריפט בודק זאת.
4. **הפלט מכיל ניתוח רגישות.** לפחות טבלה אחת של שני משתנים (למשל תשואה × דמי ניהול, או WACC × צמיחה). מודל בלי רגישות אינו גמור.
5. **בנייה רפרודוסבילית.** המודל נוצר מסקריפט `build_model.py` שמקבל קלט בלבד, כותב לתיקייה חדשה, ומוכיח: שתי ריצות → קובץ זהה (לאחר נרמול מטא‑דאטה, ראה `scripts/rebuild_compare.sh`).

## 2. חוזה לפני בנייה (חובה)

לפני כתיבת קוד, הצג למשתמש ואשר:

| סעיף | מה לציין |
|---|---|
| **סוג המודל** | DCF / תקציב / פנסיה / חיסכון / תיק |
| **קלטים** | רשימת ההנחות עם ערך, יחידה, מקור |
| **אופק ותדירות** | שנים / חודשים; תאריך התחלה |
| **פלט מדויק** | שמות גיליונות, שמות עמודות, מדדים סופיים (NPV, IRR, צבירה, קצבה) |
| **מטבע ויחידות** | ₪ / $ ; אלפים / יחידות ; נומינלי / ריאלי |
| **קריטריון "עשוי"** | verify_model.py ירוק + רגישות + rebuild זהה |

אם משהו לא ברור — שאל, אל תניח. במיוחד: **נומינלי או ריאלי**, **ברוטו או נטו ממס/דמי ניהול**, **תחילת תקופה או סופה**.

## 3. מוסכמות Excel (מעבר ל‑skill‑xlsx)

- צבעים: קלט כחול · נוסחה שחור · קישור לגיליון אחר ירוק · הנחה לאישור — מילוי צהוב.
- אחוזים נשמרים כשבר (`0.04` = 4%). תשואה שנתית שמומרת לחודשית: `(1+r)^(1/12)-1`, לא `r/12` — אלא אם המשתמש דרש אחרת ותיעדת זאת.
- שנים כטקסט. אפס מוצג `-`. שליליים בסוגריים.
- גיליון `README` ראשון: מה המודל עושה, אילו תאים לערוך, גרסה ותאריך בנייה, רשימת הנחות פתוחות.
- בדוגמאות המצורפות `horizon` נקבע בזמן בנייה ב־CLI, מסומן באפור ואינו תא לעריכה. שינוי האופק מחייב בנייה מחדש; פירוט ב־`references/checks.md`.
- RTL: כשהמודל בעברית, `sheet.sheet_view.rightToLeft = True` וכותרות בעברית; שמות טכניים (Assumptions/Calc) יכולים להישאר באנגלית.
- אין XLOOKUP/FILTER/SORT — INDEX/MATCH בלבד (LibreOffice לא מחשב אותן).

## 4. בדיקות חובה לפני מסירה

**מוסכמת מפתחות (חובה — הבדיקות תלויות בה):** ב‑`Assumptions` עמודה A = key באנגלית (`return_lt`, `fee_aum`, `wacc`, `g_terminal`…), B = תווית, C = ערך, D = יחידה, E = מקור. ב‑`Calc` עמודה A = key לשורה, B = תווית, C ואילך = תקופות (שורה 1 = אינדקס תקופה). מפתחות שורה: פנסיה `open, deposit, return, fee, withdraw, tax, close`; DCF `fcf, nopat, dep, capex, dnwc` (+ אופציונלי `assets, liabilities, equity, cash_open, cash_close, financing`); תקציב `revenue, expense, profit`. הרשימה המלאה ב‑`references/checks.md`.


הרץ `python -B scripts/verify_model.py <model.xlsx> --type pension|dcf|budget --recalc <path/to/recalc.py>` (בחר סוג אחד) ודווח את הפלט המלא. הסקריפט בודק:

- `recalc` ירוק — אפס שגיאות נוסחה.
- אין מספרים קשיחים בתוך נוסחאות ב‑Calc/Output (מלבד 0, 1, 12, 100).
- עקביות נוסחאות לרוחב כל שורת תחזית (R1C1 זהה).
- סכומי ביניים משתמשים ב־SUM או SUBTOTAL לסכימה על הטווחים המוגדרים במפרט, כולל תוצאות בעמודה B של Output.
- כל תא ב‑Assumptions מוזכר לפחות פעם אחת (הנחה יתומה = שגיאה).
- טווחי סבירות מ‑`references/checks.md` (למשל תשואה שנתית בין ‑50% ל‑+50%, דמי ניהול 0–5%).
- כל תא בטבלת הרגישות ב־Output מתאים לחישוב עצמאי, ותרחיש הבסיס מופיע פעם אחת בדיוק בכל ציר ומתאים לפלט המודל.
- מאזן: לפי סוג המודל (DCF: נכסים = התחייבויות + הון; פנסיה: יתרת סגירה = פתיחה + הפקדות + תשואה − דמי ניהול − משיכות).

לאחר מכן `bash scripts/rebuild_compare.sh` — שתי בניות, השוואה, ודיווח `IDENTICAL` / `DIFF`.

**כלל הראיות:** "המודל עובד" בלי פלט של שני הסקריפטים אינו מסירה. קוד יציאה: `0` PASS · `1` FAIL · `2` לא רץ (חסר LibreOffice/recalc — הרץ בסביבה שיש בה, לא תעקוף). זהו כלי audit של ה‑skill; באתר או ב‑pipeline כותבים שער בנייה נפרד בשפת הפרויקט ומשתמשים בקובץ הזה כמפרט בלבד.

## 5. אל תעשה

- אל תכתוב תוצאה מחושבת ב‑Python לתוך תא במקום נוסחה.
- אל תשנה הנחה שהמשתמש נתן "כי היא לא סבירה" — סמן, שאל, ותעד.
- אל תוסיף גיליונות/מדדים שלא נתבקשו. רשום אותם ב‑"נמצא, לא תוקן".
- אל תיתן ייעוץ השקעות או פנסיה — המודל מחשב, המשתמש מחליט. ציין זאת ב‑README.

## 6. קבצים נלווים

- `references/checks.md` — רשימת הבדיקות המלאה וטווחי הסבירות לפי סוג מודל. קרא לפני כתיבת verify.
- `references/pitfalls.md` — 15 טעויות נפוצות במידול פיננסי (חישוב חודשי שגוי, כפל אינפלציה, IRR על תזרים ללא סימן שלילי, דמי ניהול מהפקדה מול מצבירה, ועוד). קרא לפני בניית Calc.
- `scripts/verify_model.py` — סורק המודל ומדפיס דוח ראיות (JSON + טקסט).
- `scripts/rebuild_compare.sh` — בונה פעמיים ומשווה.
- `examples/build_pension_example.py`, `build_dcf_example.py`, `build_budget_example.py` — סקריפטי בנייה מאומתים לשלושת סוגי המודלים; העתק את המבנה שלהם (README/Assumptions/Calc/Output, מפתחות, צבעים, רגישות) כנקודת התחלה למודל חדש.
